# hanabi — Discord 弾幕オーバーレイ 設計書

- Date: 2026-08-26
- Status: Draft（ユーザーレビュー待ち）
- 関連 ADR: [ADR-0001 Electron 採用](../../../adr/0001-use-electron.md) / [ADR-0002 二層アーキテクチャ](../../../adr/0002-two-layer-architecture.md)

## 1. 概要

Discord の特定チャンネルの新着メッセージを、ニコニコ動画風の弾幕（右→左スクロール）として macOS の画面全体に、透明・最前面・完全クリックスルーでリアルタイム表示するツール。配信視聴などのシーンで、作業や視聴を邪魔せずチャットを画面に流すことを目的とする。

本書は MVP（最初に完成させる版）の設計を定義する。

## 2. 前提・確定事項

- **Discord アクセス**: Bot を対象サーバーに追加できる。正規の Bot（Gateway 接続）方式で実装する。Message Content Intent を有効化する。
- **実装基盤**: Electron（JS/TS）。受信も discord.js で統一（ADR-0001）。
- **アーキテクチャ**: 受信部と表示部を分離した二層構成。ローカル WebSocket で接続（ADR-0002）。
- **表示（MVP）**: 右→左スクロールの弾幕のみ。将来のバリエーション追加に備え、レンダラは差し替え可能なインターフェースにしておく（MVP はスクロール実装1つだけ登録）。
- **オーバーレイ挙動**: 透明・全画面・最前面・**完全クリックスルー**。
- **操作手段**: 全画面クリックスルーのため画面上で操作できない。**メニューバー常駐アイコン**を1つ置き、「弾幕 ON/OFF」「終了」のみ提供（最小限、制御パネルは作らない）。

## 3. 表示内容（MVP）

1件のメッセージで画面に流す情報：

- **メッセージ本文**（必須）。
- **送信者名**（設定で ON/OFF 切替可能。邪魔なら非表示にできる。アイコン表示も任意でオフ可能）。
- **カスタム絵文字・絵文字**: 画像として表示する。
- **URL 等の整形**: URL は短縮表示するなど、読みやすくなるよう整形する。

## 4. アーキテクチャ

```
┌─────────────────────────┐        ┌──────────────────────────┐
│  受信部 (Node/discord.js) │        │  表示部 (Electron)         │
│  ・Gateway でメッセージ受信 │  ローカル │  ・透明/全画面/最前面ウィンドウ  │
│  ・整形(URL短縮/絵文字解決)  │ ──WS──> │  ・完全クリックスルー        │
│  ・正規化イベントを送出     │        │  ・弾幕レンダラ(右→左)      │
│  ・bridge(WSサーバ)        │        │  ・WSクライアント          │
└─────────────────────────┘        └──────────────────────────┘
              ▲
              │
      メニューバー常駐(弾幕ON/OFF・終了)
```

受信部は Discord の生データではなく、表示に必要な形へ正規化したメッセージのみを送出する。

## 5. コンポーネント

各コンポーネントは単一の目的を持ち、独立して理解・テストできるようにする。

- **`receiver/`（Node）** — discord.js で Gateway 接続。指定チャンネルの `messageCreate` を購読し、正規化して `bridge` へ渡す。
- **`formatter`（receiver 内モジュール／純粋関数群）** — URL 短縮化、カスタム絵文字を画像 URL へ解決、メンション・装飾のクリーンアップ、`segments` への分割。副作用を持たず単体テスト可能にする。
- **`bridge`（ローカル WS サーバ）** — 正規化イベントを表示部へブロードキャスト。表示部が未接続/切断でも受信部は動作を継続する。
- **`overlay/`（Electron main）** — 透明・全画面・最前面・クリックスルーのウィンドウ生成（`transparent: true`, `alwaysOnTop`, `setIgnoreMouseEvents(true)`）。メニューバー常駐（Tray）で ON/OFF・終了を提供。
- **`renderer/`（Electron renderer）** — WS クライアントとして受信し、弾幕を描画。
  - **`danmaku` レンダラインターフェース** — `render(message)` を持つ差し替え可能な描画方式。MVP は「右→左スクロール」実装 (`ScrollRenderer`) を1つ登録。レーン管理（重なり回避）と画面外での破棄を行う。

## 6. データフロー（正規化メッセージ・スキーマ）

受信部 → 表示部で流す1件のスキーマ：

```json
{
  "id": "メッセージID",
  "author": { "name": "ゆーざー", "avatarUrl": "https://…" },
  "text": "整形後テキスト（URL短縮済み）",
  "segments": [
    { "type": "text",  "value": "やっほー " },
    { "type": "emoji", "url": "https://cdn.discordapp.com/emojis/….png", "name": "wave" }
  ],
  "timestamp": 1700000000
}
```

- `segments` によりテキストとカスタム絵文字画像を弾幕内で混在表示できる。
- `text` はフォールバック用途（絵文字非対応表示や将来のプレーン表示向け）にも保持する。
- `author.name` / `author.avatarUrl` は表示部の設定で ON/OFF する。

## 7. 設定

- **`.env`（gitignore 対象）** — `DISCORD_BOT_TOKEN`。
- **設定ファイル（例: `config.json` または `.env`）** — `CHANNEL_ID`、`WS_PORT`、送信者名の表示 ON/OFF、アイコン表示 ON/OFF、弾幕の流速、フォントサイズ、最大同時表示数など。
- 値は MVP では固定/ファイル編集で足りるものとし、GUI 設定画面は作らない。

## 8. エラー処理・運用

- **Gateway 切断**: discord.js の自動再接続に委ねる。
- **表示部 ⇄ 受信部の WS 切断**: 指数バックオフで再接続。受信部は表示部の生存に依存しない。
- **ポート競合**: `WS_PORT` は設定可能にし、起動失敗時は明確なエラーを出す。
- **Bot トークン/権限**: `.env` で管理。Message Content Intent の有効化手順と Bot 招待手順を README にドキュメント化する。
- **メッセージ流量過多（スパム対策）**: 最大同時表示数を設け、超過分はドロップまたはキューイング（MVP はドロップで可）。

## 9. テスト方針

- **`formatter`**: 純粋関数のユニットテスト（URL 短縮、カスタム絵文字解決、メンション整形、`segments` 分割）。
- **`bridge`**: モック WS クライアントで送受信・再接続をテスト。
- **正規化スキーマ**: 受信部の出力が定義スキーマに一致することを検証。
- **弾幕描画**: 目視確認（自動化は将来）。

## 10. MVP スコープ外（将来）

- 右→左以外の表示バリエーション（上部/下部固定、ランダム配置、エフェクト等）。差し替え可能インターフェースは用意するが実装は将来。
- 表示部の Swift ネイティブ版への載せ替え（受信部は再利用可能な設計を維持）。
- 画像・添付ファイルの弾幕表示。
- GUI 設定画面。
- 複数チャンネル同時表示。
