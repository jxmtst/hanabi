# ADR-0002: 受信部と表示部を分離した二層アーキテクチャを採用する

- Status: Accepted
- Date: 2026-08-26
- Deciders: プロジェクトオーナー

## Context（背景）

hanabi は Discord のメッセージを弾幕として画面表示する。実装基盤には Electron を採用した（[ADR-0001](0001-use-electron.md)）。

このアプリには性質の異なる2つの関心事が存在する：

1. **Discord からのメッセージ受信・整形**（Gateway 接続、再接続、URL 短縮、カスタム絵文字の解決、正規化）。
2. **弾幕としての画面表示**（透明・最前面・クリックスルーのウィンドウ、右→左スクロール描画、将来の表示バリエーション）。

要件として、表示バリエーションを将来いろいろ差し替え・追加したいこと、また将来的に表示部のみを Swift ネイティブへ載せ替える可能性を残したいことが挙がっている。これらの関心事を1つのプロセス・モジュールに密結合させると、表示の実験が受信ロジックに影響し、載せ替えも困難になる。

## Decision（決定）

アプリを**受信部**と**表示部**の二層に分離し、両者を**ローカル WebSocket**（例: `ws://127.0.0.1:PORT`）で接続する。

```
┌─────────────────────────┐        ┌──────────────────────────┐
│  受信部 (Node/discord.js) │        │  表示部 (Electron)         │
│  ・Gateway でメッセージ受信 │  ローカル │  ・透明/全画面/最前面ウィンドウ  │
│  ・整形(URL短縮/絵文字解決)  │ ──WS──> │  ・クリックスルー           │
│  ・正規化イベントを送出     │        │  ・弾幕レンダラ(右→左)      │
└─────────────────────────┘        └──────────────────────────┘
```

- 受信部は Discord の生データではなく、**表示に必要な形へ正規化したメッセージ**のみを送出する。
- 受信部内に、ローカル WS サーバとして正規化イベントを表示部へブロードキャストする `bridge` を持つ。
- 表示部は WS クライアントとして受信し、描画に専念する。

## Consequences（結果）

### Positive（利点）

- **関心の分離**：受信ロジックと表示ロジックが独立し、それぞれを単独で理解・テスト・変更できる。
- **表示バリエーションの実験が安全**：表示部だけを差し替えても受信部に影響しない。
- **表示部の載せ替えが容易**：将来 Swift ネイティブのオーバーレイに変えても、同じ WS プロトコルを話せば受信部をそのまま再利用できる。
- **耐障害性**：表示部が落ちても受信部は動き続け、再接続で復帰できる（逆も同様）。
- 正規化スキーマ（`author` / `text` / `segments` / `timestamp` 等）を境界として明確化でき、テストしやすい。

### Negative（欠点・トレードオフ）

- 単一プロセス構成に比べ**構成要素が増える**（WS サーバ/クライアント、再接続処理）。
- プロセス間通信のための**プロトコル定義とバージョン管理**が必要になる。
- ローカルとはいえポートを1つ使用する（競合時のフォールバックを考慮する必要がある）。

## Alternatives considered（検討した代替案）

### 単一プロセス（Electron 内で discord.js を直接動かす）

- 利点：構成が単純。プロセス間通信が不要。
- 欠点：受信と表示が密結合し、表示の実験が受信に波及する。表示部を Swift へ載せ替える際に受信ロジックごと作り直しになる。耐障害性も低い。
- 判断：将来の表示バリエーション追加・載せ替え要件に反するため不採用。

### Electron の main/renderer 分離のみ（IPC）で完結させる

- 利点：Electron 標準の IPC で完結し、外部 WS を持たなくてよい。
- 欠点：受信部が Electron プロセスに縛られ、表示部を非 Electron（Swift 等）へ載せ替える際に受信部を切り出せない。
- 判断：載せ替え容易性を確保するため、プロセス境界をローカル WS にする方針を採用。将来単一言語で固めたくなった場合の縮退先としては残す。
