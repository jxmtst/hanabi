# ADR-0001: オーバーレイの実装基盤に Electron を採用する

- Status: Accepted
- Date: 2026-08-26
- Deciders: プロジェクトオーナー

## Context（背景）

hanabi は、Discord の特定チャンネルのメッセージをニコニコ動画風の弾幕（右→左スクロール）として macOS の画面全体に、透明・最前面・完全クリックスルーでリアルタイム表示するツールである。

要件として重要なのは以下の点：

- 弾幕の**表示バリエーションを将来いろいろ作りたい**（色・軌道・フォント・エフェクト等）。
- Discord の特定チャンネルのメッセージを**リアルタイムで受信**する必要がある（正規手段は Bot による Gateway 接続。Bot はサーバーに追加可能なことを確認済み）。
- macOS 上で**透明・最前面・全画面・クリックスルー**のオーバーレイを実現する必要がある。
- 実験（xp）プロジェクトであり、**反復開発の速さ**を重視する。

実装基盤の候補として Electron（JS/TS）と Swift（ネイティブ macOS）で迷いがあった。

## Decision（決定）

オーバーレイ表示部およびアプリ全体の実装基盤として **Electron（JS/TS）** を採用する。Discord 受信部も同じ JS エコシステム（discord.js）で統一する。

## Consequences（結果）

### Positive（利点）

- **表示バリエーションが作りやすい**：CSS/DOM アニメーションにより、色・軌道・フォント・エフェクトのバリエーションを低コストで量産できる。本プロジェクトの中核要件に直接効く。
- **Discord 受信が最短**：discord.js が事実上の標準ライブラリで、Gateway 接続・メッセージ購読の実装が容易。表示部と同一言語で統一できる。
- **反復開発が速い**：ホットリロード等により試行錯誤のサイクルが速い。
- 透明・最前面・全画面・クリックスルーのウィンドウ（`transparent`, `alwaysOnTop`, `setIgnoreMouseEvents`）が標準機能で実現できる。

### Negative（欠点・トレードオフ）

- Chromium を同梱するため**メモリ/配布サイズが大きめ**（150MB〜）。
- ネイティブに比べ CPU/省電力面で不利。ただし弾幕テキスト程度の描画では実用上問題にならないと判断。
- macOS ネイティブの最前面制御の細やかさでは Swift に劣る。

### 中立・将来への含み

- ネイティブの軽さ・最前面制御が本当に必要になった場合は、表示部のみを Swift 実装へ差し替える余地を残す。この差し替えを容易にするため、受信部と表示部を分離する（[ADR-0002](0002-two-layer-architecture.md) を参照）。

## Alternatives considered（検討した代替案）

### Swift（ネイティブ macOS）

- 利点：最軽量・省電力で、macOS の透明オーバーレイ・最前面制御が最も洗練される。
- 欠点：Discord 接続の公式ライブラリがなく、Gateway(WebSocket) を自前実装するか非公式ライブラリ（Swiftcord 等）に依存する必要があり手間が大きい。弾幕の表示バリエーションも Core Animation で1つずつ実装するコストが高い。ビルドが遅め。
- 判断：表示バリエーションの作りやすさと Discord 受信の容易さという中核要件で Electron に劣るため不採用。ただし将来の表示部差し替え候補としては残す。

### Python + オーバーレイ GUI（discord.py + PyQt/Tkinter）

- 利点：discord.py で受信は容易。
- 欠点：macOS での透明・クリックスルー・最前面制御が Electron より難しく、弾幕アニメーション表現の作りやすさでも劣る。
- 判断：不採用。
